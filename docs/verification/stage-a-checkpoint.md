- 端末：iPhone 17 Pro のシミュレーター、iOS 26.5
- 開発環境：Xcode 27
- 使った画面：開発用の仮の画面「確認用」（[CheckpointView.swift](../../PrenatalCheckupNote/Checkpoint/CheckpointView.swift)）と、開発用メニューの「保存を失敗させる」

## 目的

段階 A で作った保存の土台（`NoteService`、元に戻す、書きかけ）を、段階 B の本番の画面を作る前に、実際に手で操作して確かめます（要件定義 v0.4 の段階 A の確認点）。自動テスト（Swift Testing 65 件）で確かめていることを、画面とアプリの終了・起動し直しを含めて、もう一度確かめるのがねらいです。

### 確認 8 の詳しい結果

| 場面 | 結果 |
| --- | --- |
| 質問を足す | 「うまくいきませんでした」の知らせが出た。一覧は変わらず、入れた文は入力欄に残った |
| 「健診後メモを書く」を押す | 知らせが出て、メモの画面は開かなかった（開く前に空の書きかけを保存する作りのため）。何も消えなかった |
| メモの画面で「保存」（直す前） | **知らせが出なかった**。何も消えなかったが、利用者には失敗が伝わらない |
| メモの画面で「閉じる」（直す前） | 書きかけの保存に失敗しても閉じてしまう作りだった。閉じたあとも知らせは出なかった |
| メモの画面で「保存」（直したあと） | メモの画面の上に知らせが出て、画面は開いたまま、本文とスイッチも残った |
| 保存できていない変更があるときの「閉じる」（直したあと） | スイッチを 1 つ切り替えて保存に失敗させたあと「閉じる」を押すと、知らせが出て、画面は閉じなかった |
| 下にスワイプ（直したあと） | 引っぱっても元に戻り、閉じなかった |
| アプリを起動し直す | 保存できていなかった変更（スイッチのオフ）は消え、最後に保存できた書きかけ（本文とスイッチのオン）に戻った（要件定義 v0.4 の「強制終了したあとは、最後に保存できた内容に戻る」のとおり） |

## 直したこと

確認 8 で見つかった 2 点を、この PR の 2 つ目のコミットで直しました。

- 失敗の知らせは、後ろの「確認用」の画面に付けていたため、メモの画面（シート）がかぶさっている間は出せず、閉じたあとも出ないまま終わっていた。メモの画面の上でも知らせを出し、後ろの画面ではシートを開いていないときだけ出すようにした。
- 「閉じる」が、書きかけの保存に失敗しても閉じていたため、失敗している間に書いた分が消えるおそれがあった。保存できたときだけ閉じ、保存できていない変更があるときは下にスワイプしても閉じないようにした。

段階 B の本番の画面でも同じことが起きないように、シートの上で起きた失敗はシートの上で知らせる、保存できていない入力があるときは閉じさせない、の 2 つを守ります。

## 気づいたこと（段階 B で扱う）

- 「健診後メモを書く」を押したときの失敗で、何も入力していないのに「入力した内容はそのままです」と出る。場面に合った文にする。
- 保存の失敗を開発用のスイッチで続けている間は、メモの画面を閉じられず、スイッチ（後ろの画面の金づち）にも手が届かない。本当の失敗は一時的なので利用者には問題ないが、確かめるときはアプリを起動し直して抜けた。段階 B では、開発用の切り替えの置き場所を見直す。
- 保存を失敗させている間に本文を打つと、1 文字ごとに書きかけの保存が失敗して知らせが出る。段階 B では、入力が 1 秒ほど止まってから書きかけを保存する（要件定義 v0.4 の決まり）ので、知らせの回数も減る。
- 確認の途中で、「保存を失敗させる」がオフのまま「保存」を押してしまい、メモが普通に保存された（「元に戻す」で取り消した）。スイッチは起動し直すとオフに戻るので、確かめる前にオンになっているかを見る。
