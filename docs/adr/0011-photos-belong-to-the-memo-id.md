# ADR 0011: 写真は「メモの ID」で持ち主を指し、縮めた写しを保存する

- 状態：採用
- 日付：2026-10-26

## 状況

段階 E で、健診後メモに写真（エコー写真など）を付けます。開発者と決めた決まり（要件定義 v0.4 の 5 章）は次のとおりです。

- 写真から選び、アプリの中に写しを保存する。1 つのメモに 5 枚まで（R-80〜R-82）。
- 選んだ写真は入力途中のメモに残し、アプリを起動し直しても残す。入力途中の内容を破棄したら写真も消す。
- 1 枚ずつ外せて、元に戻すと画像も戻る（R-84）。メモの削除を元に戻すときも、写真を戻す。
- エコー写真の文字が読めなくなるほど小さくしない。一覧には小さい画像を使う（R-83）。

写真は書きかけ（`MemoDraft`）で選び、保存すると健診後メモ（`CheckupMemo`）のものになります。SwiftData の関係（`@Relationship`）で書きかけとメモの両方につなぐと、保存のときに付け替えが要り、書きかけを消したときに一緒に消えてしまわないかを気にする必要があります。

## 決定

- 写真のモデル `MemoPhoto` は、関係ではなく `memoID`（UUID）で持ち主を指す。書きかけの ID は保存したメモの ID と同じなので（ADR 0008、S-02）、書きかけに足した写真は、保存してもそのままメモの写真になる。
- 書きかけを捨てたとき・メモを削除したときは、窓口（`NoteService`）が同じ ID の写真を同じ保存の中で消す。
- 画像は長い辺 2,400 ピクセルまでに縮めた JPEG と、長い辺 300 ピクセルの小さい JPEG を保存する（`PhotoProcessing`）。大きいほうは `@Attribute(.externalStorage)` でデータベースの外のファイルに置く。縮めるときは、画像を丸ごと広げずに縮めながら読む（ImageIO の `CGImageSourceCreateThumbnailAtIndex`）。
- 元に戻すための値（`PhotoSnapshot`）は、画像のデータごと持つ。戻せるのは直前の 1 回だけで、メモ 1 つの写真は 5 枚までなので、メモリに持っても大きすぎない。

## 理由

- 保存のときに写真を付け替えないので、「保存したら写真が消えた」「元に戻したら写真が書きかけに戻らない」が起きにくい。保存を元に戻しても、同じ ID の書きかけが戻るので、写真はそのまま書きかけのものに戻る。
- 関係を使わないので、モデルを足すだけで済み、いまのデータはそのまま開ける（自動の移行）。
- 縮めた写しを保存するので、写真アプリで元の写真を消してもメモの写真は残り（R-82）、一覧で大きい画像を読み込まずに済む。

## 影響

- 写真を消し忘れないよう、メモや書きかけを消す処理には、写真も消す処理を必ず入れる。テスト（`MemoPhotoTests`）で、捨てる・削除する・元に戻すのそれぞれを確かめる。
- 長い辺 2,400 ピクセルより大きい写真は縮まる。エコー写真の文字が読めることは、実機の大きい写真で確かめる（段階 E の最後）。
