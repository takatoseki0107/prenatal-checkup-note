# ADR 0009: シートは 1 か所で開き、失敗の知らせは一番上の画面で出す

- 状態：採用
- 日付：2026-10-25

## 状況

段階 A の確認点で、保存をわざと失敗させて確かめたところ、健診後メモのシートで保存に失敗しても知らせが出ませんでした（[段階 A の確認の記録](../verification/stage-a-checkpoint.md)）。知らせ（`alert`）を後ろの画面に付けていたため、シートがかぶさっている間は出せず、シートを閉じたあとも出ないまま終わっていました。

段階 B では、質問・健診後メモ・次の健診・持ち物・設定と、シートが増えます。どの画面で失敗しても、知らせが必ず出るようにする必要があります。

あわせて、元に戻すの帯をどれだけ出すか（ADR 0008 で画面の側に任せた点）を決めます。

## 決定

- 開いているタブとシートは `AppRouter` の 1 か所で持ち、シートは一番下の画面（`ContentView`）でまとめて開きます。
- 失敗の知らせは `noteErrorAlert` でまとめ、いま一番上に見えている画面に出します。シートを開いていないときは一番下の画面で、開いているときはシートの側で出します。
- 保存できていない入力があるシートは、下にスワイプしても閉じないようにします。
- 元に戻すの帯は、目安 6 秒で消します（R-60）。消すのは `NoteStore` が受け持ち、消すときは窓口の「元に戻す」もやめます。帯が消えたあとに戻せると、何が戻るのかわからなくなるためです。保存に失敗した操作では「元に戻す」は変わらないので、待ちも続きます。

## 理由

- シートを開く場所が 1 か所なら、「いまシートが開いているか」が 1 つの値でわかり、知らせをどこに出すかを決めやすくなります。
- 知らせの出し方を 1 つにまとめると、新しいシートを作るときに付け忘れても、レビューで気づきやすくなります。
- 帯の時間を `NoteStore` に持たせると、どのタブに帯が出ていても同じ決まりで消え、テストでも時間を短くして確かめられます。

## 影響

- 新しいシートを作るときは、`AppRouter.Sheet` に足し、シートの中に `noteErrorAlert` を付けます。
- シートの中からさらにシートを開くとき（例：健診後メモのシートから写真を選ぶ）は、そのシートの中で同じ考え方をします。
- VoiceOver のときに帯を出したままにすることは、VoiceOver に対応しないと決めたので、行いません（要件定義 v0.4 の 3 章）。
