# ADR 0007: データの変更は保存の窓口に集め、1 つの操作を 1 回の保存にまとめる

- 状態：採用
- 日付：2026-10-25

## 状況

要件定義 v0.4 では、記録を失わないことを技術の見せどころにしています（7 章）。特に健診後メモの保存は、1 つの操作で次の変更が同時に起きます。

- 健診後メモを作る
- 丸を付けた質問（外したものを除く）をメモに写し、一覧から消す
- 受診日が次の健診の日なら、次の健診を空にして、持ち物のチェックを外す

このうち一部だけが保存されると、「質問が一覧から消えたのにメモがない」のような、記録を失う状態になります。また、SwiftData のコンテキストは、既定では自動で保存します。変更の途中で自動保存が走ると、同じ状態が起こりえます。

## 決定

- 画面はデータを直接変えず、すべて保存の窓口 `NoteService` を通します。
- 窓口の 1 つの操作は、変更をすべて終えてから 1 回だけ保存します。保存に失敗したら `rollback()` で保存前に戻し、`NoteServiceError.saveFailed` を返します。
- 窓口のコンテキストは自動保存を止めます（`autosaveEnabled = false`）。
- 操作を始めるときに未保存の変更が残っていたら、混ぜないよう先に戻します。
- 保存の処理は外から渡せる形にし、テストでは「わざと失敗する保存」に差し替えます。
- テストは、メモリの中だけの保存場所ではなく、一時的なファイルの保存場所で行います。閉じて開き直しても残るかを確かめるためです。
- 健診後メモの ID は書き始めたときに決め、同じ ID で 2 回保存してもメモは 1 つにします（続けて押したときの二重保存を防ぐ）。

## 理由

- 一部だけ保存された状態を作らないことを、1 か所の決まりで守れます。操作ごとに気をつけるより、漏れが起きにくくなります。
- 失敗を差し替えで起こせるので、「保存に失敗しても質問は一覧に残り、次の健診も消えない」をテストで確かめられます。
- ファイルの保存場所を開き直すテストは、メモリの中のテストでは見つからない、保存されていない変更を見つけられます。

## 影響

- `rollback()` は、そのコンテキストの未保存の変更をすべて戻します。入力中の文は、コンテキストのモデルではなく画面の値や書きかけ（次の PR）に持ち、巻き戻されないようにします。
- 保存したあとの「元に戻す」は、`rollback()` では作れません。次の PR で、戻すための値を持つ形で作ります（R-60〜R-63）。
- お知らせの予約・取り消しは、データの保存が成功してから行います（段階 C、S-05）。`saveMemo` は、次の健診を空にしたかを結果で返します。
