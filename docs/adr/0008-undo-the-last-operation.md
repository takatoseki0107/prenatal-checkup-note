# ADR 0008: 元に戻すは直前の 1 回だけにし、戻すための値を自分で持つ

- 状態：採用
- 日付：2026-10-25

## 状況

要件定義 v0.4 では、質問の削除・健診後メモの保存・次の健診の日付を消す操作などを、画面の下の帯の「元に戻す」で戻せます（R-06、R-17、R-33）。

SwiftData の `rollback()` は、まだ保存していない変更を捨てるもので、保存したあとの操作は戻せません（ADR 0007）。`ModelContext` の `undoManager` を使う方法もありますが、複数の操作をまたいだ履歴の管理や、「新しく入れた予定は残して古い保存だけ戻す」のような例外を正しく扱うには、作り込みが要ります。ChatGPT のレビューでも、初版で複雑な履歴を作らないよう勧められました。

## 決定

- 戻せるのは直前の 1 回だけにします（R-60）。
- どの操作でも保存に成功したら、前の「元に戻す」は消えます。画面を見るだけ（読むだけ）では消えません。
- 戻す操作ごとに、戻すための値（`QuestionSnapshot` など）を `PendingUndo` として持ちます。消したモデルへの参照ではなく、独立した値で持ちます（R-63）。
- 戻すことも 1 回の保存にまとめます。失敗したら戻す前のデータのままにし、戻すための値も残します（R-63）。
- 戻すための値はメモリの中にだけ持ちます。アプリを終了すると消えます。
- 健診後メモの保存を戻すと、メモを消し、写した質問・空にした次の健診・外した持ち物のチェック・書きかけを、保存前の値（同じ ID）で戻します。

## 理由

- 直前の 1 回だけなら、戻す前に別の変更が入ることがありません。「その操作で変えたものだけを戻す」（R-61）を、例外なしで守れます。
- 値で持つので、元のモデルが消されたあとでも、同じ ID で作り直せます。
- `undoManager` に頼らないので、何が戻るかをテストで決まった形で確かめられます。

## 影響

- 削除を戻せるのは、帯が出ている間だけです。そのあとは戻せません（ごみ箱は作らない。R-19）。
- 書きかけの保存も「保存」なので、健診後メモを保存したあとに新しい書きかけを書き始めると、前の保存は戻せなくなります。新しい書きかけと、戻した書きかけがぶつからないようにするためです。
- 帯を何秒出すか、VoiceOver のときにどうするかは、画面の側（段階 B）で決めます。
