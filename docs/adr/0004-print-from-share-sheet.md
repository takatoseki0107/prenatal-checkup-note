# ADR 0004: 質問リストの印刷は、共有シートに印刷用の項目も渡して行う

- 状態：採用
- 日付：2026-10-23

## 状況

F-16（質問リストのテキスト共有・印刷、P0）では、健診ごとの質問リストと健診メモを、共有シートで送るか印刷します。診察中にスマホを使えない人のための代わりの手段です。PDF の出力は作りません。

ワイヤーの共有プレビュー画面には、「共有・印刷する」ボタンが 1 つだけあります。共有シートだけで印刷までできるかを、技術検証 TV-04 として実機で確かめました（[実機での動作確認](../verification/device-check.md)）。

## 確かめたこと（TV-04）

iPhone 17 Pro（iOS 27.0.1）での結果です。

| 方法 | 結果 |
| --- | --- |
| A. SwiftUI の `ShareLink` に文章だけを渡す | 共有シートに「プリント」が出ない |
| B. `UIPrintInteractionController` で印刷の画面を直接開く | 印刷できる。プレビューで文字が切れない |
| C. `UIActivityViewController` に、文章と `UISimpleTextPrintFormatter` を一緒に渡す | 共有シートに「プリント」が出て、印刷できる。「メモ」に送った文章は二重にならない |

## 決定

「共有・印刷する」ボタンでは、C の方法で共有シートを開きます。ボタンはワイヤーどおり 1 つのままにします。

## 理由

- 利用者は 1 つのボタンから、送信先も印刷も選べます。B のように「印刷」ボタンを別に置くと、画面の構成とワイヤーを変える必要があります。
- 印刷のために PDF を作る処理は要りません。
- 送信先は利用者が共有シートで選び、アプリが自動で送信しないという F-16 の条件を、そのまま満たせます。

## 影響

- `ShareLink` では印刷用の項目を渡せないため、UIKit の `UIActivityViewController` を使います。
- SwiftUI の画面からは、いま手前にある画面から UIKit で直接表示します（段階1の共有プレビュー画面で決定。`ShareSheetPresenter`）。`UIViewControllerRepresentable` で包んで SwiftUI のシートとして出す方法では、共有シートが閉じたときに空のシートが残らないよう、表示の状態を戻す処理が要ります。開くだけなら直接表示のほうが単純で、TV-04 の実機確認でもこの方法を使いました。
- 確認したのは iOS 27.0.1 の実機だけです。iOS 26 では、共有プレビュー画面を作るときにシミュレーターで確かめます。
- 共有先は「メモ」でしか確かめていません。ほかの共有先で文章の扱いに問題が見つかったら、渡し方を見直します。
- 文字の大きさや余白、改ページは、必要なら段階1で調整します。
- PDF を作らずにこの方法で足りるかは、要件定義のとおり利用者テストで確かめます。
